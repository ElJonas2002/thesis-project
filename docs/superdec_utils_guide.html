superdec_utils.py: plain-English guide

What every function does, the order it runs in, and which numbers you can safely change. File: src/intel_realsense/intel_realsense/superdec_utils.py (line numbers below refer to it).

SAFE TO TUNE Change it freely, then benchmark.   TRY CAREFULLY Can help, but has side effects. Always benchmark.   LEAVE ALONE Must match how the network was trained, or the math depends on it.

The big picture

This file takes one object's point cloud (from fastsam_node) and turns it into a few superquadrics (rounded boxes / cylinders / ellipsoids) that describe the object's shape. Both the ROS node (superdec_node.py) and the offline bench (scripts/superdec_offline.py) use this file, so any change here affects both.

denoiseremove stray points→ complete_shelladd fake bottom + sides→ canonical_rotationmake table = floor (+Y up)→ uniform_resampleeven out point density→ pick 4096 + normalizecentre and shrink to unit size
SuperDec networksplits points into parts + guesses shapes→ merge_stageglue parts one shape can cover, refit→ lm_stage (optional)polish each shape→ undo normalize + rotationback to camera frame, in metres

Preprocessing Neural network Merging Refinement Output

The whole story in 5 sentences.
  1. The camera sees only one side of the object, and the cloud has noise. Preprocessing cleans the cloud and makes it look like the training data: a closed surface, with the table as the floor and points spread evenly.
  2. The cloud is shrunk to fit inside a unit cube, because the network was trained on objects that size.
  3. The SuperDec network decides which point belongs to which part. It usually cuts the object into too many parts.
  4. The merge keeps the network's point-to-part decisions but ignores its shapes. It refits each part with a fast formula and keeps gluing pairs of parts that one shape can still cover.
  5. Optionally LM polishes each shape. The results are then scaled and rotated back into the camera frame.

How to test a change (do this every time)

  1. Capture a scene once (with the pipeline running): 
    ros2 service call /fastsam_node/snapshot std_srvs/srv/Trigger
# writes snapshots/<timestamp>/objNN.ply + plane.npz
  2. Run the bench with the same settings as the node. The bench flags are off by default, while the node has them on, so pass them all: 
    python scripts/superdec_offline.py --denoise --complete --canonical --uniform --merge \
       --export exports/my_test_01
# add --merge-tol 1.25 / --merge-grid 7 / --merge-cap 128 / --lm to compare
  3. Read the numbers it prints:
    • #sq: how many superquadrics each object got. Fewer is usually better, if the error stays low.
    • recon error (mm): average distance from points to the closest surface. Lower is better.
    • flatness: below 0.15 means flat slabs glued onto the visible face (bad). Above 0.35 means the shapes have real volume (good).
    • eps_prof / eps_sect: average roundness.
    • merge: X s: how long the merge took.
  4. Look at it: open exports/my_test_01/*_sq.ply (shapes) and *_seg.ply (points coloured by part), or use --viser.
  5. Write it down in docs/PROJECT_LOGBOOK.md.
  6. Ship it to the robot: the node runs the installed copy, not src/. Rebuild: 
    colcon build --packages-select intel_realsense && source install/setup.bash
ros2 run intel_realsense superdec_node --ros-args -p merge_tol:=1.25   # override params at start
Two traps.
  1. The bench has its own copy of the preprocessing order (preprocess() in superdec_offline.py). If you change the order or add a step in SuperDecRunner.prepare, change the bench too, or you will be measuring something different from what the robot runs.
  2. When this guide was written, the copy in install/ was older than src/. Rebuild before trusting what the robot shows.

N_POINTS = 4096

The exact number of points fed to the network for each object.

Whatever size the cloud has after preprocessing, exactly 4096 points are picked at random. If there are fewer, some are repeated. The network was trained with 4096, so a different number changes what it sees and can quietly hurt quality.

load_model(checkpoint_dir, device, lm_optimization=False)

Reads config.yaml and ckpt.pt, builds the SuperDec network, and puts it in inference mode.

What the network returns for each object: a fixed number of primitive "slots", each with scale, shape, rotate, trans, exist, plus assign_matrix (which point belongs to which slot).

lm_optimization=True would run LM inside the network, before the merge. The merge then throws those shapes away (it only keeps the point assignment), so that would be wasted time. Use lm_stage after the merge instead.

1 · Preprocessing: make the real cloud look like training data

SuperDec was trained on clean, complete, evenly sampled surfaces of CAD models, standing upright with +Y as up. A depth camera gives the opposite: noisy, one-sided, much denser on the visible face, and tilted at some angle. Each step below fixes one of those differences.

denoise(points, neighbours=20, std_ratio=2.0)

line 166 · SAFE TO TUNE
Removes "flying" points that float away from the object.

How

  1. For every point, measure the average distance to its 20 nearest neighbours.
  2. Points whose average is unusually large (more than std_ratio standard deviations above typical) are thrown out.
  3. Safety net: if fewer than 32 points would survive, keep the original cloud.

Why it matters

Later, the object gets scaled so its farthest point touches the edge of a unit cube. A single stray point 20 cm away shrinks the real object to a tiny blob and ruins everything after it.

Knobs

KnobLower itRaise it
std_ratio (2.0)Removes more points. Cleaner, but may eat thin parts like handles or edges.Removes fewer points. Keeps detail but lets noise through.
neighbours (20)Judges by a very local area, so it reacts more to small clumps.Judges by a wider area and is smoother. A bit slower.

complete_shell(points, normal, offset, rng, grid=64, floor_ratio=0.3, wall_ratio=0.6)

line 72 · TRY CAREFULLY · needs the table plane
The camera only sees the front and top. This invents a bottom (on the table) and side walls (straight down from the outline) so the object looks closed, like the training meshes.

Analogy: put the object on graph paper, trace its shadow, then build cardboard walls along the shadow's outline up to the object's height and lay a cardboard floor inside it.

How, step by step

  1. Height above table: for each point, how high it is above the table plane. Points below the table count as height 0.
  2. Shadow on the table: project every point straight down onto the table, which gives 2D coordinates.
  3. Graph paper: cover the shadow's bounding box with a grid × grid (64×64) set of cells. The cells stretch to the object's size, so bigger objects get bigger cells.
  4. Height map: each cell remembers the tallest point that fell in it.
  5. Tidy the shadow: fill tiny holes (morphological "closing") and spread heights one cell outward ("dilate"). A round 3×3 brush keeps round outlines round instead of square.
  6. Floor: scatter floor_ratio × N new points at height 0 over the filled cells.
  7. Walls: find the outline cells (filled minus shrunk-by-one) and scatter wall_ratio × N new points there, each at a random height between 0 and that cell's height.
  8. Return the original points plus the floor and the walls.

Each new point gets a small random offset inside its cell, and wall heights are random rather than stepped. Without that, the network sees a staircase and fits one flat slab per step.

Knobs

KnobLower itRaise it
grid (64)Coarser outline. Fine for simple shapes and fills holes better on sparse clouds.Sharper outline, but sparse clouds get "holey" shadows.
floor_ratio (0.3)A weaker bottom face.A stronger bottom face.
wall_ratio (0.6)Weaker invented sides. The network trusts the visible face more.Stronger sides. Better volume, but the invented walls are always vertical, so tapered objects (cones, bowls) look like cylinders.
uniform_resample runs afterwards and evens out density, so the ratios mostly decide whether there are enough points to cover the floor and walls. The exact proportion matters less.
The walls assume the object is a straight extrusion of its shadow. That is great for boxes, cans and bottles, but wrong for things that overhang, like a mug handle, which gets a wall going down to the table under it.

canonical_rotation(normal)

line 58 · LEAVE ALONE (the "up = +Y" part)
Builds a rotation that makes the table normal point along +Y, so "up" means the same thing it meant in training (ShapeNet uses Y-up).

How

  1. Y axis = the table normal ("up").
  2. X axis = something perpendicular to up, found with a cross product against a helper direction (world Z, or world X if up is almost parallel to Z).
  3. Z axis = perpendicular to both.

It returns a 3×3 matrix whose rows are the new X, Y, Z. Points are rotated with points @ R.T. At the end, SuperDecRunner undoes this so the shapes come back in the camera frame.

Idea to try (not tested): the spin around "up" is arbitrary, because it comes from the helper direction. Aligning X with the object's long side on the table could give the network a more consistent view.

uniform_resample(points, target=4096)

line 137 · TRY CAREFULLY
Makes points evenly spread over the surface, so the visible face doesn't dominate.

Why

The network gives out primitives roughly in proportion to how many points an area has. The camera puts most points on the visible face, so without this step that face gets several stacked slabs.

How

  1. Split space into small cubes ("voxels") and keep one point per cube. Bigger cubes keep fewer points.
  2. Find the cube size that leaves about 1.3 × 4096 ≈ 5300 points, using up to 20 rounds of "too many → bigger cubes, too few → smaller cubes" (binary search between diag/400 and diag/8).
  3. Return the result with the largest cube size that still kept at least 4096 points. If none did, return the input unchanged.

Knobs

1.3 (line 161) is the spare margin above 4096. A bigger margin keeps finer detail but less even density. Closer to 1.0 gives more even density. The bounds only limit the search range.

normalize_points(points)

line 178 · LEAVE ALONE
Moves the object's centre to (0,0,0) and scales it so it fits inside a cube from -0.5 to 0.5.

It returns the normalized points plus the translation and scale used, which are needed to undo it at the end. The network was trained in this space. From here until the final output, every size and distance is a fraction of the object's size, not metres. The bench converts errors back to mm for you.

2 · Merging: fewer, better primitives

The network is good at grouping points but tends to cut objects into too many parts. The merge keeps the grouping, ignores the network's shapes, and refits everything with a fast formula plus a small search. It then keeps gluing the best pair of parts until gluing starts to hurt the fit.

Call order: merge_stage → merge_object (once per object) → stack_groups + fit_groups → radial_distance. The functions below are explained bottom-up (smallest first).

radial_distance(local, extent, e_prof, e_sect)

line 188 · LEAVE ALONE (the math) · also used by LM checks
The ruler: how far is a point from a superquadric's surface?

Analogy: stand at the shape's centre and shine a laser at the point. The answer is how far the point is from where the laser crosses the shape's skin.

Inputs

  • local: the point in the shape's own frame (already centred and rotated).
  • extent: half-sizes (a, b, c) along the shape's x, y, z.
  • e_sect (ε₂): roundness in x-y. e_prof (ε₁): roundness along z.

It returns one number per point. 0 means exactly on the surface.

The formula (optional)

Inside-outside function: F = ( |x/a|2/ε₂ + |y/b|2/ε₂ )ε₂/ε₁ + |z/c|2/ε₁. F = 1 on the surface, below 1 inside, above 1 outside.
Radial distance = |point| × | 1 − F−ε₁/2 |.

It is computed with logarithms (log, logaddexp) because powers like 1/0.1 = 10 overflow to NaN when done directly.

It only checks that the points lie on the surface. It does not penalise parts of the surface that have no points near them. A shape can be bigger than the data in empty regions and still score well. That matters if you change the scoring.

fit_groups(pts, mask, grid=5, shrinks=(0.85, 0.95, 1.0), budget=4_000_000)

line 209 · TRY CAREFULLY · the workhorse
Fits one superquadric to each group of points, for all groups at once, with no slow optimisation. It returns the shapes and how well each one fits.

Step by step (for every group in parallel)

  1. Centre = the average of the group's real points (the mask skips padding). This becomes trans.
  2. Orientation: PCA. The covariance matrix's eigenvectors give the 3 main directions of the points. These become rotate.
  3. Try 3 axis orders. ε₁ always acts on the shape's local z, so it matters which main direction is called z. It tries z = the longest, the thinnest and the middle direction.
    Why: a short, wide can has two almost equal directions, so PCA's order is basically random. The wrong choice makes a box fit better than a cylinder.
    If an order turns out mirrored, one axis is flipped. That is harmless because SQs are symmetric.
  4. Size: rotate the points into each candidate frame. Half-size on each axis = the farthest point on that axis, like a tight box around the points.
  5. Grid search over what's left:
    • shrink ∈ {0.85, 0.95, 1.0}: shrink the box a bit, since the farthest point is often noise.
    • ε₁ ∈ grid values from 0.1 to 1.9 (with grid=5: 0.1, 0.55, 1.0, 1.45, 1.9).
    • ε₂ ∈ the same values.
    With the defaults: 3 shrinks × 5 × 5 = 75 combos × 3 axis orders = 225 candidate shapes per group.
  6. Score each candidate = average radial distance of the group's points. Keep the lowest.

Returns: params (scale, shape, rotate, trans) and the residual, the best score, used by the merge to decide.

Speed comes from replacing optimisation with "formula + lookup table": one 3×3 eigendecomposition and 225 scores per group. The old refine stage ran an Adam optimiser per candidate pair and took about 19 s per object. This takes milliseconds.

stack_groups(points, groups, cap, rng)

line 266 · SAFE via merge_cap
Packs groups of different sizes into one equal-sized array for the GPU.
  1. Width = the size of the biggest group, but never more than cap.
  2. Groups bigger than cap are randomly subsampled down to cap points.
  3. Smaller groups are padded with zeros, and mask marks real points as True.

cap = merge_cap (192) while deciding merges, and 4 × cap (768) for the final refit. Lower is faster but noisier: decisions are based on fewer points and change more between runs. Higher is more stable but slower.

merge_object(points, groups, tol, rng, grid, cap)

line 278 · SAFE (tol) / CAREFUL (the rule)
For one object: keep gluing the pair of parts that one shape describes best, until any further glue would make the fit noticeably worse.

Step by step

  1. Fit every current group on its own and remember its residual (how well it fits).
  2. Repeat while there are at least 2 groups:
    1. Make every possible pair (A, B) and combine their points.
    2. Fit one shape to each combined group, all in one batch.
    3. For each pair compute
      ratio = error of the combined fit ÷ max(error of A, error of B)
      In words: how much worse is one shape for both, compared with the worse of the two separate fits?
    4. Take the pair with the smallest ratio.
    5. If that ratio is above tol (1.15, i.e. more than 15% worse): stop.
    6. Otherwise glue them: A becomes A+B, and B is deleted.
  3. Return the final list of groups (point indices only, not shapes).

Example: a mug split into 3 stacked slabs plus a handle

RoundBest pairRatioResult
1slab 1 + slab 2≈ 1.0merge (one cylinder fits both)
2slabs 1-2 + slab 3≈ 1.0merge
3body + handle≈ 3> 1.15, stop → 2 primitives

Good to know

  • The ratio can be below 1: two badly fitted halves of a box can fit better as one box.
  • There is no "are they touching?" check. Far-apart parts just get a big error and are never chosen.
  • It is greedy: it never un-glues. Each round tests n(n−1)/2 pairs, and there are at most n−1 rounds.

Things you could change

ChangeEffect
tol ↑ (e.g. 1.3)Merges more, gives fewer and coarser shapes.
tol ↓ (e.g. 1.05)Merges less, gives more and tighter shapes.
base = max(...) → point-weighted average of A and BStricter: a tiny badly fitted part can no longer "excuse" a bad merge.
Add a gap/adjacency checkPrevents gluing parts that don't touch, even if one shape happens to cover both.

merge_stage(x, out, rng, tol=1.15, grid=5, cap=192)

line 308 · entry point of the merge · CAREFUL for its hard-coded numbers
Takes the network output, merges each object, does a careful final fit, and returns results in the same format as the network so nothing downstream notices.

Step by step

  1. Read the network: each point goes to its strongest slot (assign_matrix argmax). A slot is "alive" if exist > 0.5.
  2. Build groups = the point indices of each alive slot.
    • Groups with fewer than 32 points are dropped as too small to fit reliably.
    • If nothing is left, the whole object becomes one group.
  3. Merge each object with merge_object.
  4. Final refit of the surviving groups, done more carefully than the quick fits used for deciding:
    • 4× more points: 4 × cap = 768.
    • A finer roundness grid: 2 × grid + 3 = 13 values per exponent (0.1, 0.25, 0.4 … 1.9).
  5. Package: fill the same keys the network uses (scale, shape, rotate, trans, exist, assign_matrix). Unused slots get harmless defaults (tiny size, exist = 0), and assign_matrix becomes a clean one-hot.

Hard-coded numbers you may want to touch

NumberLineLower itRaise it
32 (min points per group)317Keeps small real parts, but also noisy fragments.Drops more fragments; small details vanish.
0.5 (alive threshold)311Uses more of the network's slots.Uses only confident slots.

primitive_errors(x, out)

For every primitive: the average radial distance of its own points to its surface. NaN if it has no points.

lm_stage(x, out, steps=5)

line 358 · SAFE (lm, lm_steps) · CUDA only
Runs a few Levenberg-Marquardt (LM) steps to fine-tune all 11 numbers of every merged shape. It keeps the result only for shapes that actually got better.

Step by step

  1. Measure each alive primitive's error (primitive_errors) as "before".
  2. Clamp the exponents slightly inside (0.1, 1.9). LM converts them with a formula that becomes ±infinity exactly at 0.1 and 1.9, and the grid search produces those exact values. That is what LM_SHAPE_MARGIN is for.
  3. Run LMOptimizer from the SuperDec package for steps iterations.
  4. Measure "after". For each primitive, accept the LM version only if it is alive, has no NaN/inf, and its error went down. Otherwise keep the merge version.
  5. Return the result plus stats (accepted count, before/after errors). The bench prints these.

So LM can never make a shape worse. At worst it wastes time.

KnobEffect
lm_steps (5)More steps polish more but are slower. Check the "accepted" count in the bench: if it's 0, LM isn't helping.
LM_SHAPE_MARGINLEAVE It only exists to avoid infinity.

4 · Glue: the class the node actually calls

class SuperDecRunner

line 397 · the ROS node creates one of these and calls it every cycle
Point clouds in (camera frame, metres) → superquadrics out (camera frame, metres).

__init__(...): settings

It stores every on/off switch and merge/LM setting, loads the model once, picks the GPU if one is available, and creates the random generator (seed=0). If you ask for LM without CUDA, it warns and turns LM off.

prepare(points, plane, frame): preprocessing for one object

Fixed order (each step only runs if its switch is on):

denoise → complete_shell (needs the plane) → rotate with frame (canonical) → uniform_resample → pick exactly 4096 points at random.

The order matters. complete_shell must run before the rotation because it uses the table plane in camera coordinates. Denoise goes first so stray points don't get walls built under them.

__call__(clouds, plane): the full run

  1. Build the canonical rotation once from the table normal.
  2. For each object: prepare → normalize_points. Remember each object's shift and scale.
  3. Stack all objects into one batch and run the network once.
  4. merge_stage (if merge), then lm_stage (if lm).
  5. Undo everything for each object, keeping only alive primitives:
    • size × scale; centre × scale + shift (back to metres).
    • undo the canonical rotation on centres and orientations (back to the camera frame).
    • exponents are unitless, so they stay as they are.
  6. Return one dict per object: {'scale', 'shape', 'rotate', 'trans'}.
To add a new preprocessing step, write a function, call it inside prepare, add a switch in __init__ and a parameter in superdec_node.py, and add the same step to preprocess() in the bench.
